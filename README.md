# 再逛一次

一个面向城市再访者的交互式行程规划助手。当前专注香港、上海和柏林：先通过自然语言理解预算、时间、同行人数、去过什么与这次想换什么，再生成少量方向卡和可调整的每日行程。

## 主要能力

- 自然语言收集目的地、天数或剩余时间、人数和当地预算。
- 区分不想重复、仍想重温、上次喜欢和本次兴趣。
- 用“角色视角”组织方向卡，让用户从建筑师、当地居民、厨师、生物学家等人的观察方式重新认识城市。
- 生成每日地点、住宿、餐饮、交通和费用建议，并支持预算、单日强度与费用调整。
- 使用 OpenStreetMap、Nominatim 和 OSRM 展示地点连接与步行路线。
- 保存当前标签页的对话与行程状态；模型或地图失败时不会覆盖已有方案。

## 本地运行

需要 Node.js 22 或更高版本。

```bash
npm install
cp .env.example .env
npm run dev
```

在 `.env` 中填写：

```env
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-v4-pro
```

然后打开 <http://127.0.0.1:5173>。运行期间不要关闭执行 `npm run dev` 的终端。

如确实需要代理，可设置 `TRAVEL_PLANNER_PROXY=http://127.0.0.1:端口`。项目不会自动使用系统代理。

## 内容生成机制

方向卡不是预先写死的“角色 × 地点”链接，而是每次根据用户状态现场生成：

1. `revisit-catalog.js` 提供地点素材库。数据库中可以保留其他城市，但产品入口只开放香港、上海和柏林；三城目前各有 32 个基础素材。
2. `content/content-v1.json` 配置角色、角色的观察方法、通用行动类型和去重规则。修改配置即可扩充角色或改变生成策略。
3. `content-store.js` 根据用户的兴趣、愿意重温的内容、排除项、片区、体力要求和已展示历史召回地点；保留每项排序理由，刷新方向时排除本会话已经展示过的地点。
4. DeepSeek 读取用户槽位、候选地点、角色池和行动类型，现场组合最多 3 张方向卡，并生成本次专属的问题、观察行动、推荐理由与代价。证据不足时允许少给或不给。
5. 服务端只接受配置中真实存在且标签与角色关键词有交集的地点和角色组合，过滤行动类型 ID，并强制同一批卡片地点与角色不重复。模型失败时保留原状态并允许重试，不用模板卡掩盖故障。

因此地点与角色没有强绑定：同一个地点可以在不同用户、不同偏好下由不同角色重新组织；同一个角色也能进入不同地点。可配置内容控制边界，模型负责组合与表达。

## 项目结构

```text
.
├── index.html
├── server.js
├── planner-api.js             # 会话、模型调用、行程校验与地图路线
├── revisit-catalog.js         # 地点素材数据库与开放城市配置
├── content/content-v1.json    # 角色、行动类型与生成规则

├── src/
│   ├── entry.js
│   ├── examples.js
│   ├── planner-app.js
│   └── planner.css
└── test/planner.test.js
```

## 内容配置

```bash
npm run content:check
npm run content:preview -- 柏林 architect
```

配置只有 `draft`、`published` 和 `archived` 三种启用状态，不包含虚假的人工审核流程。

## 测试

```bash
npm test
```

自动测试覆盖槽位清洗、三城范围、生成式方向卡、去重刷新、方向承诺、行程调整和地图路线。真实模型效果仍需单独做端到端验证。

## 当前边界

- 地点、酒店、餐厅、价格和营业信息不是实时预订数据，出行前仍需确认。
- 费用是当地住宿、餐饮、交通和游玩的粗估，不含往返机票或火车。
- 路线图用于理解地点如何连接，不能替代实时导航。
- 会话只保存在本机内存和当前浏览器标签页，没有账号或跨设备同步。
