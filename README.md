# 再逛一次

一个面向城市再访者的交互式行程规划助手。它不直接输出大段攻略，而是先理解预算、时间、同行人数和再访偏好，在必要时给出少量玩法方向，再生成可调整的每日行程。

当前支持：香港、上海、深圳、柏林、米兰、马德里。每次规划一座城市。

## 主要能力

- 使用自然语言收集目的地、天数或剩余时间、人数和当地预算。
- 分别识别不想重复、仍想重温、上次喜欢和本次感兴趣的内容。
- 没有明确方向时，DeepSeek 从 48 个本地锚点中动态组织最多三张玩法卡，选择后再生成行程。
- 选方向时可以继续自然语言提问；咨询只返回回答，不会偷偷选择或替换卡片。
- 用户反悔时会撤销旧要求，并消除“既排除又想去”等冲突状态。
- 使用 DeepSeek 生成每日地点、住宿、餐饮、交通和费用建议。
- 支持调整预算、修改单日安排和锁定不希望改变的日程。
- 使用 OpenStreetMap、Nominatim 和 OSRM 展示地点连接与步行路线。
- 已有行程时，模型或地图请求失败不会用错误结果覆盖当前内容。
- 当前标签页保存并展示用户与助手的聊天记录，刷新后可以继续查看。

## 本地运行

需要 Node.js 22 或更高版本。

```bash
npm install
cp .env.example .env
npm run dev
```

在 `.env` 中填写：

```env
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-v4-flash
```

然后打开 <http://127.0.0.1:5173>。

密钥只由本地 Node.js 服务读取，不会发送到浏览器，也不会提交到 Git 仓库。

## 产品流程

1. 用户输入再访需求。
2. 系统只追问缺少的必要信息。
3. 用户核对人数、时间、预算及预算口径。
4. 没有明确玩法时，系统展示三个具体方向；选方向时仍可自然语言补充要求。
5. DeepSeek 生成卡片化行程，服务端校验天数、预算结构、排除项和选中锚点。
6. 用户可以继续追问、调整单日、微调预算或查看路线。

## 动态方向卡

`revisit-catalog.js` 不是 48 张固定成品卡，而是六座城市各 8 个可组合锚点。代码与模型的职责分开：

1. 代码根据城市、明确排除项、兴趣和本会话已经展示过的内容筛选锚点。
2. DeepSeek 从候选锚点中选择最多三个，动态组织标题、配套体验、适配理由和必要代价。
3. 三张卡尽量在片区、主题、体力或费用上形成明显差异。
4. 服务端只接受候选池中的锚点 ID；模型生成的库外锚点会被忽略。
5. 用户选中的锚点、配套体验、节奏与必要交通必须进入最终行程，明确不想重复的内容不得出现。
6. DeepSeek 组卡失败时使用代码排序结果兜底，用户仍可继续操作。

这种设计让可审核的地点范围保持稳定，同时避免每次展示完全相同的话术和组合。

## 当前边界

- 48 个锚点是验证用初稿，尚未逐条完成人工审核；模型只能在候选池内选择锚点，但会动态组织标题、配套内容和适配理由。
- 地点、营业时间、酒店、餐厅和价格不是实时预订数据，出行前仍需确认。
- 费用是当地住宿、餐饮、交通和游玩的粗估，不含往返机票或火车。
- 路线图依赖公共地图匹配，只用于理解地点如何连接，可能发生同名误配或道路绕行，不能替代实时导航。
- 路线按照行程卡片顺序分段绘制并显示方向；生成提示要求地点顺路，但当前还没有使用地图算法强制优化行程顺序。
- 会话和聊天记录只保存在本机内存及当前浏览器标签页；点击重新开始、关闭标签页或清除站点数据后会消失，没有账号、跨设备同步或长期记忆。
