# 再逛一次

## 现在的产品

只有一个入口：`index.html`。产品服务已经去过一座城市、这次想换种玩法的用户，当前支持香港、上海、深圳、柏林、米兰和马德里，一次规划一座城市。出发前旅行和已经在当地的短时安排使用同一个入口。

用户先用自然语言提供人数、时间、当地预算和再访经历。条件明确时可以直接生成；没有方向时先展示三张本地玩法卡，用户选中后由 DeepSeek 生成现有行程卡片。

封板文件 `constraint-demo.html`、`hk-data.js` 不变；旧实现及旧测试移至 `archive/legacy/`，不再加载或提供接口。

## 启动

Node.js 22+。首次运行先执行 `npm install`，再在本机 `.env` 填写 `DEEPSEEK_API_KEY` 和可选的 `DEEPSEEK_MODEL`，运行 `npm run dev`，打开 http://127.0.0.1:5173 。密钥只在服务端使用。修改服务端或环境变量后需重启；服务端会读取本机 HTTP/HTTPS 代理环境变量。

## 交互

- 先说需求，再确认人数、人民币预算和全员/每人口径。出发前需要支持城市和天数，日期与出发地可选；途中需要支持城市、剩余小时、人数和预算。
- “去过”“不想重复”“还想重温”和“这次想尝试”分别保存。没有方向时从当前城市候选目录中展示最多三张玩法卡；点击“按这个方向安排”才确认选择。
- 当前玩法目录是产品验证用初稿，不是实时精选。选中的玩法锚点必须进入生成结果；明确排除项出现时，服务端拒绝提交新方案。
- 每天一张卡，先露出主题与地点顺序，住宿、餐饮、交通及费用按需展开。
- 每天可“保留”、变轻松、换个安排。单日操作只替换该日，并在卡片内提示地点数、住宿、餐饮及费用发生的实际变化；锁定的天由代码保留，不靠模型自觉。未改变日的地图不会被清空。
- 每天可按需点击“查看路线”：服务端用 Nominatim 结合当天城市匹配坐标，再用 FOSSGIS OSRM 步行服务按卡片顺序计算道路折线、距离和连续步行时间；页面直接叠加 OSM 底图瓦片。部分地点匹配成功时保留地图，并明确距离覆盖哪些站；路线不参与生成，也不会在地图失败时改动行程。
- 可以继续问“适不适合带爸妈”；模型判断为问题时只返回短答，保留原方案。
- 预算统一表示住宿、餐饮、当地交通和游玩的“当地行程预算”，不含从出发地往返的机票或火车。滑块为原输入上下500元；点击调整才调用模型。服务端重新计算估算合计，超预算如实提醒。
- 途中使用“从现在起”的相对时间段，代码检查时段顺序、是否超出剩余时间以及住宿费用是否为零。转场是否现实仍未地图核验。
- 等待或失败时保留旧方案。浏览器 sessionStorage 保存当前标签页的会话快照；服务端重启或会话过期后，刷新会校验并恢复浏览器保存的方案、预算和锁定日程，对话历史不恢复。

## 文件

- `src/entry.js`：统一入口。
- `src/planner-app.js`、`src/planner.css`：卡片、对话、锁定、预算及反馈。
- `planner-api.js`：DeepSeek 调用、服务端会话、生成与修改校验、地图定位与路线计算。
- `revisit-catalog.js`：六座城市的再访玩法初稿、城市别名和简单排序。
- `server.js`：本机静态服务和 `POST /api/planner`。
- `test/planner.test.js`：流程、锁定、局部修改、失败保留、短时限制、追问恢复和路线顺序测试。
- `src/examples.js`：6 个首页示例，对应香港、上海、深圳、柏林、米兰和马德里的再访需求。点击仅填入输入框，不自动调用模型。
- `archive/legacy/`：旧实现和测试，仅供参考；当前测试命令不执行归档测试。

## 能力边界

这是模型知识与本地玩法初稿生成的可交互草案，**不是联网查证或预订结果**。候选玩法尚未经过产品作者逐条审核；地点、酒店、餐厅、价格、营业和交通可行性均待确认。费用只是粗估，默认不含往返出发地的机票/火车，不能承诺真实不超预算。

路线图只表达已匹配地点按当前顺序怎样通过步行道路连接。地点搜索可能出现同名误配；部分路线的距离不代表全天完整距离。连续步行时间不包含游览、排队、实时封路和公共交通；页面明确标注“不是实时导航”。公共 Nominatim 查询串行且间隔至少1.1秒，并做内存缓存；地图只在用户点击时加载，适合本机低频验证，不是生产级服务。

每版支持1–7天，途中半小时至24小时。确认后可以通过追问修改天数、人数和预算，条件与新方案校验成功后一起生效，失败时一起回滚。缩短行程如果会移除已锁定的天，会要求先解锁。当前换城市仍建议重新开始；锁定粒度为整天，尚无单地点锁定、跨次旅行记忆或商家实时报价选择。

自然语言理解仍可能遗漏信息或误判意图，需要用户在确认卡核对。校验失败时不更新旧方案。没有登录、长期存储或生产级限流，只监听本机，不应直接公开部署。

## 验证

`npm test` 为构造数据测试，不消耗模型额度。当前覆盖11项流程，包括六城限制、再访追问、玩法选择与锚点保留，以及地图完整匹配、部分匹配、零匹配、道路不连通、组合地名回退和渡轮识别。浏览器端与后端验证结果应分别报告，不能用接口成功代替完整体验成功。
